# E02 W8 — Ablation · 반복 신뢰성 · 비용 대비 효과

새 API 호출 없이 기존 원자료(`results/main/main-002`, 240 trial; 재현 `results/replication/w6-v3-20261109`, 180 trial)만 다시 계산했다. 계산 코드: [analysis/w8_ablation.py](w8_ablation.py), 결과: [analysis/w8_ablation.json](w8_ablation.json).

## 설정

- **개입(intervention) C2:** 스킬 읽기 직후 "전제를 현재 근거와 대조하라" 지시 + 근거 위치 힌트(작업 공간 파일 목록 확인, 소비자 코드·설정·출처 메타데이터 등 근거 파일 종류 언급).
- **Ablation C (요소 X 제거):** 같은 지시에서 **위치 힌트만 뺀 조건**. C2 − C가 위치 힌트 요소의 효과다.
- **기준선(baseline) B:** 스킬만 제공, 사전 확인 지시 없음.
- 과제 3개(graph·csv·events) × 환경 2(E0·E1) × 근거 위치 2(L2·L3) = 12 셀, 셀당 반복 5회. 모델은 `gpt-5.4-mini-2026-03-17`, reasoning effort `low`(`configs/model.json`).
- **반복 신뢰성:** 반복 간 편차는 반복 1~5 각각의 성공률의 표준편차(pp). pass^3은 셀 안에서 반복 1·2·3이 모두 성공한 셀의 비율이다(반복 3회를 사전에 정함). pass^5는 탐색적 보조 지표다.
- **비용:** 리스트 가격 기준 상한(캐시 할인 미적용), `trials_all.jsonl`의 `cost_usd` 합계.

## 대조 (percentage point, 기술 통계)

| 비교 | main-002 | 재현 (w6-v3-20261109) |
| --- | --- | --- |

## 해석

1. **Ablation:** 같은 "전제 대조" 지시만으로는 성공률이 오르지 않았다(C − B: −5.0pp, 재현 −1.7pp). 전체 효과는 위치 힌트를 더했을 때 나타났다(C2 − C: +16.7pp, 재현 +13.3pp). 두 실행에서 같은 방향이었다.
2. **효과가 어디에 몰렸는가:** 전체 개입 효과는 E1/L3에 집중됐다. 이 셀에서 C2는 9/15, B와 C는 모두 0/15였다. 셀별로는 graph E1/L3 +100pp, csv E1/L3 +80pp다. 그 밖의 셀은 대부분 0이다. 예외로 **events E1/L2에서는 C2가 B보다 −40pp**(5반복 중 2건)였고 재현에서도 같았다. 효과가 모든 과제에 고르게 나타난 것은 아니다.
3. **반복 신뢰성:** 평균 성공률은 올랐지만 pass^3은 B와 거의 같다(9/12 → 9/12; 재현 9/12 → 10/12). 즉 개입은 "가끔 성공하던 셀을 한 번 더 성공시키는" 효과에 가깝고, 모든 반복을 안정적으로 성공시키는 효과는 근거가 약하다.
4. **비용:** C2는 trial당 비용이 B보다 37% 높고(토큰 +41%), 성공 1건당 비용은 +18%다($0.01154 → $0.01364). 성공률 이득은 비용 증가를 조금 넘는 수준이다. 여기서 "값어치가 있다"는 결론은 조심스럽다.

## 한계 (결과를 보기 전에 정한 것과 사후 관찰을 구분)

- 과제 3개 × 모델 1개다. 셀 12개 중 두 셀(graph·csv E1/L3)이 효과의 대부분을 만들었다. 모집단에 대한 추론은 하지 않는다.
- main-002의 반복 5회는 **같은 입력 seed(20261020)를 공유**한다(v5에서 고친 레거시 설계). 반복 간 편차는 모델 샘플링 변동만 반영한다. 입력 변동 효과는 측정하지 않았다.
- `main-002` manifest에는 `code_dirty: true`(커밋 43089ed 기준)가 기록돼 있다. 재현 시 이 점을 확인해야 한다.
- 비용은 리스트 가격 상한이다. 실제 청구액과 다를 수 있다.
- ablation은 "위치 힌트" 요소 전체를 한 번에 뺐다. 파일 목록 확인 문구와 파일 종류 언급을 따로 뺀 조건은 없다.
- pass^3의 반복 수 3과 셀 정의는 이 문서에서 정했다. 결과를 보고 바꾸지 않았다.

## 추가 확인: 새 입력 seed 5개 (E1/L3, 실제 실행)

main-002와 재현 실행이 같은 입력 seed를 공유하는 한계를 줄이려고, 파일럿에 쓰지 않은 새 seed 5개(20261201~20261205)로 B·C·C2를 E1/L3에서 한 번씩 돌렸습니다. 실행 설정은 `configs/plan_w8_freshseed_*.json`, 원자료는 `results/replication/w8fresh-*/`입니다. 모델과 도구 설정은 기존 실행과 같습니다.

| 조건 | 합계 (15 trial) | graph | csv | events | 금액 / trial | 토큰 / trial |
| --- | --- | --- | --- | --- | --- | --- |
| B (스킬만) | 1/15 | 1/5 | 0/5 | 0/5 | $0.00798 | 7,921 |
| C (지시만) | 1/15 | 0/5 | 1/5 | 0/5 | $0.00901 | 8,832 |
| C2 (지시 + 위치 힌트) | 9/15 | 5/5 | 4/5 | 0/5 | $0.01213 | 12,786 |

- 실제 비용: 45회 합계 $0.437 (리스트 가격 상한, 캐시 할인 미적용).
- 모든 trial은 `agent_finished`로 끝났습니다. API 오류나 한도 초과는 없었습니다.
- 앞선 main-002·재현 결과의 방향이 새 입력에서도 그대로 나왔습니다. C2만 효과가 있었고, 위치 힌트 없이 지시만 준 C는 효과가 없었습니다.
- events는 세 조건 모두 0/5라서, 위치 힌트가 events를 풀지는 못했습니다.

**한계:** 이 확인은 E1/L3 셀만 봤고, seed마다 반복이 1회라 pass^3은 계산할 수 없습니다. E0와 L2는 포함하지 않았습니다. 그래서 앞의 표(반복 5회 × 셀 12개)를 대체하지 않고, 입력이 달라져도 효과가 유지되는지를 보는 보조 확인으로만 씁니다.
