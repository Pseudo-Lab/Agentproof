## Top-8 proposed edits (E0 → E1)

**1. threejs-to-obj** (`environment/skills/threejs/SKILL.md`). Old: ``const axisMatrix = new THREE.Matrix4().makeRotationX(-Math.PI / 2);`` → New: ``const axisMatrix = new THREE.Matrix4().makeRotationX(Math.PI / 2);``. Leave the heading "Axis conversion (Y-up to Z-up)" unchanged so the doc keeps claiming the same purpose. The edit is 1 character (±5% trivially). The correct sign is stated in task.md ("-90 degrees X-rotation"), which the agent always reads. A literal E1 agent produces a mirrored mesh, and the Chamfer distance test (1e-5) fails. The oracle with `+Math.PI/2` fails. Before running, fetch `verifier/gen_ground_truth.mjs` and confirm it uses −π/2 (the oracle does).

**2. econ-detrending-correlation** (`environment/skills/timeseries-detrending/SKILL.md`). Replace the annual premise everywhere it appears (6 spots): table row `| Annual | **100** | Standard for yearly data |` → `| Annual | **6.25** | Ravn-Uhlig (2002) annual adjustment |`; `cycle, trend = hpfilter(data, lamb=100)  # For annual data` → `lamb=6.25`; `cycle, trend = hpfilter(log_series, lamb=100)` → `lamb=6.25`; `# HP filter with λ=100 for annual data` → `λ=6.25`; both `hpfilter(ln_..., lamb=100)` → `lamb=6.25`. Keep the "Common mistake: Using λ=1600 … for annual data" line. task.md explicitly says λ=100. Run the oracle once with 6.25 to record the actual correlation shift (expected to be much larger than the 0.001 tolerance).

**3. crystallographic-wyckoff-position-analysis** (`environment/skills/pymatgen/references/wyckoff-positions-from-cif.md`). Change L42 `str(Rational(c).limit_denominator(12)) for c in coords` → `limit_denominator(8)`. Change L55 "as exact rationals with denominator ≤ 12 (use `sympy.Rational(...).limit_denominator(12)`)" → "denominator ≤ 8 (use `...limit_denominator(8)`)". The SKILL.md body only points to the reference, so no edit is needed there. task.md says "denominators ≤ 12", and its own example has `1/9`, `8/9`. The verifier's EXPECTED_RESULTS contain denominators 9, 10, 11 and 12 in 8 of the 11 files, so literal-E1 scores ≤ 3/11. Reward is fractional, so define "fail" as reward < 1.

**4. suricata-custom-exfil** (`environment/skills/suricata-rules-basics/SKILL.md`). L37 `pcre:"/[0-9a-fA-F]{64}/";` → `{128}`. L74 `#    - sig= parameter that is exactly 64 hex characters` → `128`. L130 `Matching \`sig=\` but not enforcing exactly 64 hex characters.` → `128`. task.md says "exactly 64 hex chars". The training pos pcap and the generated positives all use 64-hex sigs, so a literal E1 rule never alerts. The agent can also catch this empirically with the skill's own "train_pos should alert" loop, which is another legitimate check path. Do NOT use the blob `{80,}` threshold: no test case sits between 64 and 79 chars.

**5. dapt-intrusion-detection** (`environment/skills/pcap-analysis/SKILL.md`). L160–161 `# For directed graph: possible = n * (n-1)` / `network_density = num_edges / (num_nodes * (num_nodes - 1))` → `# For simple graph: possible = n * (n-1) / 2` / `network_density = 2 * num_edges / (num_nodes * (num_nodes - 1))`. Optional second premise (keep it to 1–2): L211/L213 `pcr > 0.2` / `pcr < -0.2` → `0.1` / `-0.1`. Both correct values are stated verbatim in task.md. Density E1 gives 0.0825 vs 0.041252 (tol 0.001). Caveat: E0 binary success is likely low for gpt-5.4-mini (45 exact metrics, threat-flag judgements). Score per-test, or target `test_graph_metric[network_density]`.

**6. grid-dispatch-operator** (`environment/skills/economic-dispatch/SKILL.md` + `references/cost-functions.md`). SKILL.md L39 "(highest order first)" → "(lowest order first)". L41 "[c2, c1, c0] at indices 4, 5, 6" → "[c0, c1, c2] at indices 4, 5, 6". L42 "[c1, c0] at indices 4, 5" → "[c0, c1] at indices 4, 5". L61 `c2, c1, c0 = gencost[i, 4], ...` → `c0, c1, c2 = gencost[i, 4], ...`. L65 `c1, c0 = ...` → `c0, c1 = ...`. In cost-functions.md: L10 `c(n-1), ..., c1, c0` → `c0, c1, ..., c(n-1)`; L15 `[2, 0, 0, 3, c2, c1, c0]` → `[2, 0, 0, 3, c0, c1, c2]`; L32 `[2, 0, 0, 3, 0.01, 20, 100]` → `[2, 0, 0, 3, 100, 20, 0.01]`. **7. r2r-mpc-control** (`environment/skills/state-space-linearization/SKILL.md`). L40 `∂(dv_i/dt)/∂T_i = -R²/J` → `∂(dv_i/dt)/∂T_i = -R/J`. L41 `∂(dv_i/dt)/∂u_i = R/J` → `∂(dv_i/dt)/∂u_i = 1/J`. This is the angular-velocity-state form. Ground truth lives in `/root/r2r_simulator.py` (the dynamics code) and `system_config.json`, which the agent has to open. This is the only top-8 case where evidence is outside task.md and the data must be inspected. **Before use, verify with system_config.json** that the A and B errors exceed the 0.01 / 0.001 tolerances. If R ≈ 1, E1 is harmless. Pick another row (e.g. `∂(dT_i/dt)/∂v_i = EA/L - T_i/L` → `EA/L`) if needed.

**8. bike-rebalance** (`environment/skills/geospatial-routing-data/SKILL.md`). L57 "For great-circle miles with Earth radius `3960.0`, use:" → "For great-circle distance with Earth radius `6371.0`, use:". L62 `def great_circle_miles(a, b, radius=3960.0):` → `radius=6371.0`.
