# Base와 SLACT의 BF16 100문제 비교

동일한 SWE-bench Verified 100문제에서 Gemma 4 31B BF16으로 각 조건을 1회 실행한
초기 실험의 결과다. **Base는 55문제, SLACT는 68문제를 해결했다.** SLACT의 평균
입력 토큰은 20.1%, 도구 호출은 19.4% 감소했다. 탐색 recall은 낮아졌고, 판정 가능한
호출의 도구 실패율은 높아졌다.

2026-11-10에 기존 실행 기록을 현재 지표로 재분석했다. 원자료의 `PUSH`는 이 문서에서
**SLACT**로 표기한다. 아래 수치는 당시 G+V′ 구현의 결과이며, 최신 작업 버전이나
QAT 모델의 5회 반복 실험 결과로 해석하지 않는다.

## 실험 조건과 방법

| 항목 | 조건 |
| --- | --- |
| 모델 | `google/gemma-4-31B-it`, BF16 |
| 평가 문제 | SWE-bench Verified에서 초기 개발에 사용하지 않은 문제를 추출한 고정 100문제 |
| 표본 추출 | seed 20261031, 데이터셋 revision `78f471bf655a3137b2e8a75af1501690ec009ec3` |
| 실행 수 | Base 100건 + SLACT 100건, 문제당 각 조건 1회 |
| 실행 한도 | 문제당 600초, context 32,768토큰, observation 5,000자 |
| Base | 기존 mini-swe-agent의 bash 명령 인터페이스 |
| SLACT | 같은 인터페이스에 검색 문맥 보강 G와 자동 검증 피드백 V′ 적용 |
| 분석 범위 | `qat_scorecard_v7`, `phase_v1`, `--model-family bf16` |

SLACT는 기존 프롬프트와 모델이 호출하는 도구를 유지하면서 환경에서 정보를 보강한다.

- **검색 문맥 보강:** 기존 `grep` 검색 결과를 매칭된 정의와 주변 코드 구조에 맞춰
  재구성하고 출력 한도 안에 담는다.
- **자동 검증 피드백:** 소스 수정을 감지하면 관련 공개 테스트를 백그라운드에서 실행하고,
  완료된 결과를 이후 일반 명령의 출력에 붙인다. 모델이 새 도구를 선택하거나 별도의
  호출 문법을 익히지 않아도 피드백이 전달된다.

초기 V′는 관련 테스트 파일을 최대 3개 선택했다. 아래 회귀율은 이 선택 테스트의
성적이 아니라, 최종 제출 패치에 대한 공식 PASS_TO_PASS 판정이다.

## 주요 결과

| 주요 지표 | Base | SLACT | 변화 |
| --- | ---: | ---: | ---: |
| **Issue Resolution Rate** | **55%** | **68%** | **+13%p** |
| 입력 토큰 / 문제 | 377,439 | 301,719 | −20.1% |
| 출력 토큰 / 문제 | 8,442 | 7,753 | −8.2% |
| Tool Calls / Task | 32.75 | 26.39 | −19.4% |
| End-to-End Latency | 451.77초 | 417.63초 | −7.6% |
| 코드 탐색 recall — S1 블록 | 83.72% | 81.13% | −2.59%p |
| 코드 탐색 recall — S1 줄 | 83.20% | 79.91% | −3.29%p |
| Tool Failure Rate¹ | 9.48% | 12.26% | +2.78%p |
| Timeout 종료 | 36건 | 27건 | −9건 |
| Context 초과 종료 | 1건 | 0건 | −1건 |
| Regression Rate² | 15.46% · 15/97건 | 10.20% · 10/98건 | −5.26%p |

비용은 성공·실패를 모두 포함한 100문제 평균이다. 토큰은 각 문제의 전체 모델 호출에
대한 누적 사용량, 호출 수는 모델의 bash 도구 호출 수, 시간은 기록된 과제별 경과 시간이다.
변화율은 반올림 전 수치로 계산했다. 백분율 지표의 차이는 퍼센트포인트(%p)다.

¹ 문제별 `실패 호출 / (성공 호출 + 실패 호출)`의 평균이다. 비0 종료 또는 확인된
편집 변경 없음이 실패에 해당한다. 테스트 실패와 `grep` 미매칭도 포함하므로 인터페이스
오사용률과 같지 않다. 편집 전후 상태가 없어 판정할 수 없는 호출은 제외하며,
문제별 판정 가능 비율의 평균은 **Base 90.35%, SLACT 90.05%**다.

² 유효한 공식 P2P 판정이 있는 문제 중 P2P 실패가 하나 이상인 문제의 비율이다.
P2P는 기존에 통과하던 테스트를 뜻한다. Base 3문제, SLACT 2문제는 유효한 P2P 판정이
없어 분모에서 제외했다. 공식 실패 목록에는 미실행 테스트가 포함될 수 있으므로,
이 수치만으로 코드 변경이 실제 회귀를 일으켰다는 인과관계까지 확정하지 않는다.

S1은 **첫 제품 코드 수정 시도 이전**에 전달된 모든 observation의 참조 줄을 합쳐
중복 제거한 누적 노출 recall이다. 블록 recall은 참조 줄을 하나 이상 보여 준 블록의
비율이고, 줄 recall은 실제 보여 준 참조 줄의 비율이다. 수정 없이 종료한 경우에는
종료까지의 관측을 사용한다. 모델의 이해도나 파일 단위 정답률을 직접 측정하지 않는다.

## 종료 상태와 해석

Timeout과 context 초과는 최종 해결 여부와 별개인 **종료 상태**다. Timeout으로
끝났지만 남아 있던 최종 패치가 공식 채점에서 해결된 경우가 Base 7건, SLACT 9건이다.
따라서 timeout 종료 36건과 27건을 모두 미해결로 세면 안 된다. Timeout 종료 중
미해결은 각각 **29건, 18건**이며, context 초과 1건은 Base의 미해결이다.

이 비교에서는 해결률과 평균 비용이 함께 개선됐지만 탐색 recall과 도구 실패율까지
모두 개선되지는 않았다. 각 조건 1회 실행이므로 반복 간 변동은 추정할 수 없다.
또한 G와 V′를 함께 적용한 결과라 두 구성요소의 개별 기여를 분리하지 않는다.
당시 기록에 없는 편집 전후 snapshot과 독립 검증 근거는 미측정으로 남겼으며,
독립 검증 지표 V1–V4를 공식 최종 채점으로 대신 채우지 않았다.

## 결과 파일과 출처

- [summary.json](summary.json): 기존 단일 평가기의 전체 집계 원문. 역사적 식별자
  `BASE`와 `PUSH`를 유지하며 이 문서의 Base와 SLACT에 각각 대응한다.
- [task-metrics.csv](task-metrics.csv): 200개 실행의 주요 지표, 종료 상태, 최종 결과,
  trajectory와 제출 패치의 SHA256. 기존 분석에서 필요한 필드만 내보냈으며,
  빈 셀은 미측정이다. 백분율은 0–1 비율로 저장한다.
- [provenance.json](provenance.json): 모델·표본·반복 수, 원본 결과 경로와 파일 해시,
  평가기 버전 및 검증 결과. 경로는 원래 ACI-Lens 작업 디렉터리 기준이다.

원자료는 `results/vheldout100-solve-gemma-B-obscomp`와
`results/vheldout100-solve-gemma-push-obscomp`에 보존되어 있다. 전체 재분석은
`results/bf16-base-push-original100-current-metrics-20261110/scorecard`에 있다.
200개 실행 모두 최종 판정이 원래 공식 결과와 같고, trajectory와 공식 보고서의
해시도 보존되었음을 확인했다. 재분석 과정에서 모델이나 벤치마크 테스트를 새로 실행하지 않았다.

이 공유 자료에는 집계와 문제별 요약을 담았다. 전체 trajectory·채점 로그·평가기 소스는
포함하지 않으므로 원로그부터 다시 측정하려면 원래 작업 디렉터리의 자료가 필요하다.
